1. Introduction Générale

1.1 Contexte et Problématique

Dans un environnement universitaire en constante évolution, la gestion efficace des espaces de travail partagés constitue un enjeu majeur. Les salles de conférence, de réunion et de formation représentent des ressources précieuses dont l'utilisation optimale nécessite une coordination rigoureuse.

La gestion manuelle ou semi-manuelle des réservations engendre plusieurs difficultés récurrentes observées à l'ITEAM University :

  • Conflits de réservation : Chevauchements fréquents dus à l'absence de vérification en temps réel de la disponibilité.
  • Sous-utilisation des espaces : Absence de données exploitables sur les taux d'occupation et les tendances d'utilisation.
  • Gestion inefficace des équipements : Difficulté à suivre l'état et la disponibilité du matériel audiovisuel.
  • Manque de visibilité : Les utilisateurs ne disposent pas d'une vue claire des créneaux disponibles.
  • Absence d'aide à la décision : Aucun mécanisme intelligent pour recommander les salles les mieux adaptées.

1.2 Solution Proposée

Objectif principal : Développer un Système de Gestion de Réservation pour Salles de Conférence complet, intelligent et entièrement conteneurisé, permettant de centraliser, automatiser et optimiser la réservation des salles et la gestion des équipements associés.

Notre solution repose sur une architecture à double backend avec un frontend web réactif :

  • Frontend : Application web React.js / TypeScript avec interface intuitive
  • Backend Principal : Java Spring Boot pour les opérations métier
  • Backend IA : Python Flask pour les fonctionnalités d'intelligence artificielle
  • Base de données : MySQL 8.0 avec schéma normalisé
  • Infrastructure : Docker et Docker Compose pour le déploiement

1.3 Objectifs du Projet

Fonctionnels

  • Interface intuitive de réservation
  • Validation automatique des disponibilités
  • Gestion complète des équipements

  • Rapports et statistiques

Intelligents (IA)

  • Recommandation intelligente de salles

3.2 Modules Fonctionnels

Module 1 : Gestion des Salles de Conférence

  • Catalogue des salles avec informations détaillées (nom, capacité, localisation, étage, surface)
  • Recherche et filtrage multi-critères (capacité, localisation, équipements disponibles)
  • Gestion CRUD complète par les administrateurs et gestionnaires
  • Indication de disponibilité en temps réel

Module 2 : Réservation et Confirmation

  • Formulaire de réservation complet avec sélection de salle, date, heure et participants
  • Validation automatique : détection des conflits de créneaux en temps réel
  • Vue calendrier interactive (jour/semaine/mois) avec code couleur par statut
  • Gestion des récurrences (quotidienne, hebdomadaire, mensuelle)
  • Annulation et modification avec notification aux parties concernées

Module 3 : Gestion des Équipements

  • Inventaire complet : projecteurs, microphones, tableaux blancs, systèmes de visioconférence
  • Suivi du statut en temps réel (disponible, en utilisation, maintenance, hors service)
  • Signalement de pannes avec formulaire de description et suivi de l'état de réparation
  • Journal de maintenance avec historique des interventions

Module 4 : Tableau de Bord Administratif

  • Vue d'ensemble synthétique : réservations du jour, taux d'occupation, alertes en cours
  • Gestion CRUD des utilisateurs avec attribution de rôles
  • Validation/refus des réservations en attente
  • Configuration des paramètres système

Module 5 : Notifications et Rappels

  • Rappels automatiques configurables (15 min, 30 min, 1h avant)
  • Notifications pour confirmations, modifications et annulations
  • Alertes administratives pour conflits et pannes d'équipement
  • Système de marquage lu/non-lu avec compteur

Module 6 : Rapports et Statistiques

  • Statistiques d'utilisation : taux d'occupation par salle, fréquence de réservation
  • Visualisations graphiques interactives (histogrammes, camemberts, courbes)
  • Analyse des heures de pointe et des périodes creuses
  • Activité par utilisateur et département

5. Conception et Modélisation

5.1 Schéma de la Base de Données

La base de données MySQL comprend 8 tables normalisées en 3NF :

TableDescriptionRelations
usersUtilisateurs du système avec rôles RBAC—
roomsSalles de conférence avec métadonnées→ equipment (1:N)
equipmentInventaire du matériel par salle→ rooms (N:1)
reservationsRéservations avec statut et récurrence→ users, rooms, equipment
reservation_equipmentTable de liaison réservations-équipementsN:M pivot
notificationsNotifications utilisateurs→ users, reservations
feedbackÉvaluations post-réservation→ users, reservations
maintenance_logJournal de maintenance des équipements→ equipment, users

5.2 Modèle de Données Principal

-- Entités clés et leurs relations users (id, email UNIQUE, password_hash, firstName, lastName, role, department, isActive) ↕ (1:N) reservations (id, user_id FK, room_id FK, title, start_time, end_time, participants_count, status) ↕ (N:M via reservation_equipment) equipment (id, name, type ENUM, room_id FK, status ENUM, serial_number) ↕ (N:1) rooms (id, name, capacity, location, floor, surface_area, is_active) notifications (id, user_id FK, reservation_id FK, type ENUM, message, is_read) feedback (id, reservation_id FK, user_id FK, rating INT, comment, sentiment ENUM) maintenance_log (id, equipment_id FK, reported_by FK, description, status ENUM)

6.3 Sécurité Implémentée

Mécanismes de sécurité :
  • Authentification JWT (HS256) avec expiration configurable
  • Hashage des mots de passe BCrypt (force 12)
  • Contrôle d'accès basé sur les rôles (RBAC) via @PreAuthorize
  • CORS configuré avec origines autorisées
  • Protection CSRF désactivée (API stateless)
  • Gestion centralisée des exceptions avec messages appropriés

7. Fonctionnalités d'Intelligence Artificielle

7.1 Architecture du Backend IA

Le backend IA développé en Python Flask expose 5 modules distincts communicant avec le backend Java via des appels REST internes :

🎯 Recommandation de Salles

  • Scoring multi-critères (0-100)
  • Capacité vs. participants
  • Équipements disponibles
  • Historique utilisateur
  • Raison de recommandation

📊 Prédiction de Demande

  • Analyse 90 derniers jours
  • Prévision N semaines
  • Détection pics académiques
  • Heures de pointe
  • Occupation par salle

🔍 Détection d'Anomalies

  • No-shows récurrents
  • Monopolisation de salle
  • Durées anormales
  • Incohérence capacité
  • Niveaux de sévérité

💬 Assistant Conversationnel

  • Détection d'intention (10 catégories)
  • Réponses contextuelles
  • Suggestions de suivi
  • Extraction d'entités
  • Langue française

7.2 Analyse des Sentiments

Le module d'analyse des sentiments traite les retours utilisateurs après chaque réservation :

  • Algorithme : Analyse lexicale rule-based adaptée au français
  • Dictionnaire positif : 20+ termes (excellent, parfait, super, fonctionnel...)
  • Dictionnaire négatif : 20+ termes (mauvais, défaillant, problème...)
  • Gestion de la négation : Détection des mots de négation dans une fenêtre de 2 mots
  • Output : POSITIVE / NEUTRAL / NEGATIVE avec score de confiance (0-1)
Algorithme de Recommandation (Score 0-100) :
  • Capacité adéquate : 40 points (ratio optimal 1-1.5x)
  • Équipements disponibles : 30 points (proportionnel au matching)
  • Historique utilisateur : 20 points (salles fréquemment réservées)
  • Localisation/étage : 10 points (préférences selon groupe)
